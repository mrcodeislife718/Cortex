# Cortex Completion Standard

Cortex is complete only when the packaged product is a verifiable software factory that remains simple to use as an IDE.

The baseline is not visual similarity. Cortex must deliver VS Code-class professional IDE completeness, Cursor-class AI coding and agent execution, Replit-class integrated execution/deployment assistance, JetBrains-class semantic intelligence and refactoring safety, and Zed-class responsiveness. Cortex-specific superiority must then be demonstrated through the System Graph, persistent evidence-backed engineering knowledge, governed multi-agent execution, capability security, transactional changes, independent verification, failure locality/recovery, model independence, low-resource operation, cost governance, production awareness and open interoperability.

The authoritative machine-readable contract is `architecture/full-product-contract.json`. The existing `architecture/superiority-contract.json` remains the comparative architecture/evidence contract. Neither contract is evidence that the product is complete. They define what must be implemented and proven.

A feature is not `PASS` because source code, UI chrome, a mock, a placeholder, a successful compile, a package artifact, or a process-start smoke test exists. `PASS` requires the relevant packaged-user workflow or independently inspectable backend behavior to execute and produce verifiable evidence. A control that renders but has no working interaction path is a failure.

The desktop must have one authoritative workbench owner. Workspace selection, Explorer, edit/save, search, Git, tasks, terminal, language intelligence, debugging, extensions, assistant/agent execution, settings, recovery and subsystem health must be integrated through stable contracts. Optional service failure may degrade its own surface but must not make the editor unusable.

Technical-superiority claims require a competitor baseline, Cortex measurement, reproducible workload, metric direction, threshold, evidence source and freshness. Missing comparative evidence is not superiority. At 1x, 10x, 100x and success-too-well scale, Cortex must preserve developer work and degrade selectively instead of globally collapsing.

The final release gate crosses the real user boundary: fresh machine -> download -> install -> authenticate -> open repository -> edit -> save -> terminal -> Git -> debug -> AI task -> agent modification -> tests -> commit -> restart -> restore -> update. Commercial deployment, owned production credentials, external signing/notarization and actual platform distribution remain external evidence and must never be inferred from repository-only tests.
